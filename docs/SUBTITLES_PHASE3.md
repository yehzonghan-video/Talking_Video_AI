# 第三階段：自動繁體字幕

流程：**完成分析 → 保存粗剪 → 產生字幕 → 修字／分段 → 保存 → 預覽 → SRT或MP4**。

## 操作

1. 在「AI影片粗剪」沿用上傳及「開始分析」，確認並保存剪輯時間軸。
2. 到「五、自動字幕」按「由現有辨識產生字幕」。沿用聲學辨識的實際口播，不用原稿補寫，也不呼叫Gemini。
3. 表格秒數是**剪輯後時間**。直接修正字幕，修改起訖時間；新增／刪除列可拆句或合句。新列需填時間與文字。不能重疊、倒置或超出影片。
4. 選基本字幕或重點字幕：都是白色粗體、黑描邊、水平置中。重點樣式在「黃色重點」填該段已有的文字，多個用 `｜` 分隔。可調字體大小與距底部百分比。
5. 按「保存字幕與樣式」。建議每段1～2行、每行約12個中文字，文字可換行。預覽、SRT和MP4只使用已保存內容。
6. 「預覽此段字幕畫面」只產生單張畫面，不重編整部影片；「產生粗剪預覽」則產生較小的完整影片。
7. 下載SRT，或勾選輸出確認後按「輸出MP4」。開啟字幕會燒錄，關閉則輸出無字幕粗剪；關閉不會刪掉修字。字幕開關立即保存，表格與樣式需按保存。

## 分段與時間同步

使用標點、中文詞界、測量到的停頓及閱讀長度選擇短句，不按固定字數猜時間；OpenCC轉繁體台灣用字。字幕內容仍需檢查辨識錯字與專有名詞。

字幕保存原片時間錨點，依最新已確認保留片段映射：

```text
輸出時間 = 原片時間 − 此保留片段原片開始 + 此保留片段輸出開始
```

例如刪原片5～10秒，原片10～15秒字幕改到輸出5～10秒。被刪詞語不輸出，恢復剪輯版本時按原片錨點還原。介面、SRT、單張預覽與MP4共用此映射。

剪輯切到一個詞，或改變人工修過字幕的內容範圍時，會標示待確認；確認前阻止字幕交付，避免猜測要刪哪些修字。可修正分段／時間並勾「已確認」後保存，也可先關閉字幕輸出無字幕影片。

只有整句時間的短句沿用聲學起訖；長句不按字數捏造時間，需手動確認或補充詞語時間。在「字幕時間映射與重新產生」勾選後可補充：只對缺乏可用詞語時間的長句擷取音訊重新辨識，其餘沿用，不呼叫Gemini。失敗保留原辨識及已保存字幕。重新產生字幕會取代修字，需明確勾選；一般重跑／調樣式不重辨識。

## Cloud與本機依賴

`requirements.txt` 新增 `jieba==0.42.1`、`fonttools==4.60.1`。`packages.txt` 包含 `ffmpeg`、`fonts-noto-cjk`、`fontconfig`；Community Cloud更新部署時需等Python及系統依賴安裝完成。

使用FFmpeg的libass字幕濾鏡與Noto Sans CJK TC，不依賴Windows路徑。實際檢查字型cmap是否包含繁體字與字幕字元，缺字就停止燒錄，避免方框。SRT不需要字型；無字幕影片不需要libass。

本機執行「安裝影片功能.bat」；舊FFmpeg缺libass時安裝器更新本專案副本，不改系統PATH。Windows預設微軟正黑體粗體，管理者可用環境變數 `SUBTITLE_FONT_PATH` 指定完整TTF／OTF／TTC，仍須通過字形檢查。可讀取舊的無字幕專案JSON；新JSON備份包含字幕與樣式。

## 效能與保留資料

- 文字／滑桿調整及Streamlit重跑不執行輸出；只有按鈕才處理。字幕預覽以內容、樣式及剪輯雜湊快取，每專案保留少量近期預覽。
- ASS、字型副本與補充辨識WAV處理後清理；不刪原片、正式輸出或時間軸。字幕開關／修字不覆蓋先前成品，但介面不會把舊樣式成品當最新成品。
- 濾鏡與編碼執行緒限制為2，降低共享主機記憶體峰值。輸出仍保留原畫面比例及既有音畫驗證，直橫式皆可用。
- 影片、逐字稿、字幕檔與資料庫均在Git忽略目錄，不進公開GitHub。Cloud本機儲存不保證永久保存；請下載剪輯JSON、原片、SRT與成品備份。

## 架構及測試

核心在 `core/subtitles/`：資料模型、分段、必要的補充對齊、雙向時間映射、修字保存、SRT／ASS、字型與燒錄資源。介面在 `ui/subtitles.py`。只增加VideoProject預設欄位，第一階段資料表、ABC、Gemini及第二階段分析保持原架構。

自動測試涵蓋繁體、詞界、分段、刪重講後時間前移、跨切點確認、人工分段／修字、版本還原無重複、備份相容、SRT與安全ASS、實際直橫式MP4燒錄／無字幕輸出、音畫同步、中文字形／字型缺失／libass缺失、預覽快取、UI不重送AI／ASR，以及補充辨識失敗保留資料。
