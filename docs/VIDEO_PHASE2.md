# 第二階段：AI 影片粗剪

使用流程：**已儲存腳本 → 上傳手機連續拍攝的影片 → 分析 → 確認／調整 → 預覽 → 輸出 MP4**。

## 安裝

第一階段可照原方式使用。影片功能首次安裝請雙擊 `安裝影片功能.bat`，或執行：

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-video.txt
.\.venv\Scripts\python.exe tools/install_ffmpeg.py
```

安裝器從 FFmpeg 官網列出的 Gyan Windows 發行來源下載，驗證 SHA256，僅寫入本專案的 `tools/ffmpeg/`。已有可執行的本機副本便會沿用，不修改系統 PATH。Linux 可安裝系統的 `ffmpeg` 套件；`packages.txt` 供 Community Cloud 安裝系統工具，但仍須安裝 `requirements-video.txt` 並考量記憶體限制。

接著雙擊 `開啟系統.bat`，瀏覽 `http://127.0.0.1:8501`，選擇側欄 **AI 影片粗剪**。本機語音辨識與人工剪輯不需要 Gemini 金鑰；開啟語意分析時沿用第一階段金鑰及模型設定。

首次分析會下載公開的 Faster-Whisper `small` 模型（約數百 MB），之後直接讀取本機快取。此台開發電腦已備妥 Small／Tiny 模型及 FFmpeg。模型與影片均不會上傳 Git。

## 操作

1. 在第一階段先儲存腳本。影片頁選擇該腳本，上傳 MP4／MOV，再按「建立剪輯專案」。只改選檔案不會建立專案，也不會在每次重新執行時重複處理。
2. 系統檢查容器、影片長度、畫面及音軌，並解碼完整影片以檢查損壞。顯示原始檔名、解析度、大小、格式與標題。儲存當時的完整腳本及腳本版本快照。
3. 按「開始分析」。本機完成語音辨識、腳本文字比對、停頓及重講分析。首次模型下載可能較久；頁面顯示目前階段。沒有音軌時顯示提示，仍可人工剪輯；輸出會建立無聲 AAC 音軌。
4. 可選擇加入 Gemini 語意分析。介面會說明：**只傳送這個專案的腳本快照與辨識文字，原片及音訊留在本機**。未勾選時完全不呼叫 Gemini。
5. 表格顯示建議時間與原因。未勾選「刪除／縮短」的區間完整保留。只有安全長停頓預先勾選；語音、重講、不確定內容必須逐項勾選「人工確認」才可刪除。可修改開始／結束秒數，修改後同樣必須確認。
6. 按「確認並保存這份剪輯時間軸」建立新版本。若想恢復某段，取消該段的刪除勾選後再保存。手動新增片段需先試聽並勾選確認。所有已保存版本可查看及恢復；恢復會追加一版，保留全部歷史。
7. 按「產生粗剪預覽」，系統才產生較小的預覽檔。原片也能從指定秒數開始試聽。
8. 確認後勾選輸出確認，再按「輸出 MP4」。依最新已保存時間軸輸出；表格中未保存的調整不會加入。輸出可播放、下載，預設檔名為 `影片標題_粗剪.mp4`，已處理 Windows 無效字元與保留名稱。

重新整理會根據網址 `video` 識別碼開啟已保存的專案。確認時間軸在 SQLite 裡，不只存在 Session State。表格尚未按保存的調整屬於未確認內容，重新整理可能遺失。

## 語音與時間依據

- 使用 Faster-Whisper／CTranslate2，在 CPU 執行 INT8 `small` 多語模型；指定中文辨識，再由 OpenCC 轉成台灣繁體用字。
- FFmpeg 先轉為16 kHz、單聲道、16-bit PCM，並按原片時間軸補齊音軌起點。模型直接接收 PCM 樣本，避免再經另一套解碼器造成版本或時間差異。
- 使用 VAD 與 word timestamps。時間來自模型對**真實音訊的聲學對齊**，不是 Gemini 根據文字猜測。輸出時間仍有誤差，尤其含糊發音、噪音、語速快或跨句邊界，不能宣稱逐影格精準。
- 每段保存起訖、辨識全文與可用詞語時間。辨識／剪輯信心皆為 `null`；不將未校準的數字包裝成正確率。
- Gemini 只收到片段 ID、文字與腳本句子，**收不到也不能改寫剪輯時間**。回覆的 ID 必須存在且連續，再由程式對應回已驗證的聲學時間。

## 保守剪輯判斷

- 文字相似度與順序用來提出線索；低相似度只標示待確認，不能視為錯誤。語意分析可標示合理改寫、可能漏講／需重拍。
- 重講分析涵蓋鄰近單句、未完成前綴、多句重講及多次重複。這些全部預設保留。合理強調不因重複字詞而直接刪除。
- FFmpeg `silencedetect` 分析實際波形。低於0.5秒不列入；預設大於1.5秒才建議縮短，原則保留0.4秒自然呼吸。門檻、保留秒數與音量判斷值均可調。
- 若靜音範圍碰到辨識語音，先向內縮至不碰到語音安全邊界的最大範圍；不足以安全修剪時，改為人工確認。實際保留停頓可能較長，原因會標示保守保留的秒數。
- 所有區間都驗證有限數值、非負、開始小於結束、不超出影片、不刪掉整片。重疊刪除取聯集，反算保留區間；不得藉重疊刪除整片。語音刪除須明確確認。
- AI 失敗時保留已完成的辨識及本機建議，使用者可人工繼續；不以假結果代替。

## 非破壞性儲存與輸出

新建剪輯專案保存於原 SQLite 的新增 `video_projects` 表，第一階段表格不變。原片以 UUID 資料夾與固定內部檔名保存，使用者檔名只當顯示資訊。每支原片記錄 SHA256；輸出前後都核對，拒絕原片被外部替換的情況。

```text
core/
├── transcription/
│   ├── provider.py            # 可替換 ASR 契約、Faster-Whisper、PCM
│   ├── transcriber.py         # 音訊擷取及暫存清理
│   └── alignment.py           # 聲學來源與時間驗證
├── editing/
│   ├── script_matcher.py      # 腳本文字比對
│   ├── repetition_detector.py # 單句／多句重講線索
│   ├── edit_planner.py        # 本機建議、Gemini ID 語意分析
│   └── edit_validator.py      # 決策、語音保護與人工確認
└── video/
    ├── schemas.py             # 媒體、片段、時間軸、專案資料模型
    ├── ffmpeg.py              # 安全參數陣列執行／逾時處理
    ├── media_probe.py         # FFprobe 與完整解碼驗證
    ├── assets.py              # AssetStore、UUID檔案隔離、SHA256
    ├── uploader.py            # 上傳／快照／原片恢復
    ├── silence_detector.py    # 波形靜音分析
    ├── timeline.py            # 刪除聯集、保留區間與合法性
    ├── renderer.py            # 重新編碼、預覽與MP4輸出驗證
    ├── project_manager.py     # SQLite持久化、版本衝突、JSON恢復
    └── service.py             # 可持續恢復的分析／確認／還原流程
ui/video.py                   # 新增的繁體中文操作頁
tools/video_e2e.py             # 真實影片本機驗收工具
```

影片核心沒有 Streamlit 依賴；AI 不執行 FFmpeg，只有驗證後的數字進入程式建立的濾鏡。FFmpeg 呼叫不用 shell，也不接受 AI 命令文字。

精確切點採解碼再編碼，非關鍵影格複製：保留段分別使用 `trim/atrim` 及時間歸零，串接為 H.264、yuv420p、AAC、MP4，加入約8毫秒的音訊淡入淡出。來源旋轉與非正方形像素會正規化，保留顯示比例，不強制直式。輸出後重新解碼並驗證長度、編碼、音畫起點與音軌長度。

預設目錄：`data/media/<專案UUID>/`；臨時 WAV 在辨識結束或失敗後刪除；輸出濾鏡及失敗輸出在結束後清理。另可手動清理預覽及暫存，不刪原片、正式輸出或時間軸。`AssetStore` 留有日後物件儲存替換介面；目前尚未實作遠端物件儲存。

## 備份恢復

下載「剪輯專案 JSON」，並另外保存「原始影片備份」。JSON 含原始腳本快照、辨識、建議及全部已確認版本，不含影片。匯入會建立獨立副本，不覆蓋既有專案。接著重新連結原片，必須符合原 SHA256 與媒體資訊；下載的輸出成品可以另外保存。

第一階段的「全部腳本 JSON」仍只備份腳本，**不包含剪輯專案及媒體**。Community Cloud 本機磁碟不保證永久保存，因此備份 JSON 及原片缺一不可。

## 可選設定

```powershell
$env:WHISPER_MODEL = 'small' # 快速測試可用 tiny；精準度通常較低
$env:WHISPER_MODEL_DIR = 'D:\Talking_Video_AI\models\whisper'
$env:MEDIA_ROOT = 'D:\Talking_Video_AI\data\media'
$env:FFMPEG_PATH = 'C:\ffmpeg\bin\ffmpeg.exe'
$env:FFPROBE_PATH = 'C:\ffmpeg\bin\ffprobe.exe'
```

`WHISPER_MODEL`、`WHISPER_MODEL_DIR`、`MEDIA_ROOT` 也可放在 Streamlit Secrets；FFmpeg 兩個路徑使用環境變數，或系統 PATH／專案 `tools/ffmpeg/bin`。

## 真實影片端到端驗收

用手機錄一段包含一次口誤重講、一次整段重講、兩秒以上停頓與刻意強調的影片，另存拍攝腳本為 UTF-8 TXT：

```powershell
.\.venv\Scripts\python.exe tools/video_e2e.py --video 'D:\素材\口播.mp4' --script 'D:\素材\腳本.txt' --model small
```

驗收工具在 `artifacts/video-e2e/<本次識別碼>/` 建立獨立資料庫、原片副本、辨識／專案 JSON 與 MP4。它**不呼叫 Gemini**，只套用安全停頓縮短，重講保持供人工確認。請播放輸出、聽字尾及接句、確認比例與原片 SHA256。語意判斷與人工刪除請再用網站驗收。

## 已知限制與後續

- 可信任單人／內部使用，尚無登入、租戶隔離、背景工作佇列與雲端永久物件儲存。不同專案的檔案以 UUID 隔離，不代表有使用者權限隔離。
- 上傳最多500 MB、15分鐘、最多200保留片段；Streamlit 上傳及下載仍消耗主機記憶體，不適合多人同時處理大檔。CPU辨識與重新編碼會需要時間，處理時請保持頁面開啟。
- 同專案同時在多視窗變更，使用 revision 偵測正式保存衝突；不提供中途暫停工作與工作排程。分析成功的辨識先保存，後續AI失敗可繼續恢復。
- 聲學時間與語意判斷都可能有錯；寧可保留。需用實拍影片確認收音、工程專有詞、重講及自然節奏。本機合成語音測試通過不等於所有手機實拍情境皆已驗收。
- HDR／10-bit手機影片轉為H.264 yuv420p，未提供專業HDR色彩管理；極端VFR、特殊多音軌與非常大的解析度仍需個別驗收。
- 下一步優先實拍驗收、穩定儲存、登入及背景工作。未加入字幕、背景音樂、特效、提詞器或專業剪輯軟體匯出。
