# 第三階段完整優化：影片與字幕編輯器

## 日常操作

1. 開啟「AI 影片粗剪」，選擇原有專案，或沿用選腳本／上傳／分析流程。
2. 完成語音辨識後按「由現有辨識產生字幕」。字幕來自實際錄音；不會為字幕另呼叫 Gemini。若已有字幕，直接載入。
3. 影片右側的「字幕」頁可修字、換行、改樣式與黃色重點。點字幕清單或字幕時間軸即可定位；拖曳區塊可移動，拖左右把手可改起訖時間。秒數欄保留精細調整。
4. 拆分前先將播放位置移到該段中間，選擇文字中的分割處，再按「依播放位置拆分」。未選文字位置時依中文詞界分割。可合併下一段、撤銷與重做。
5. 上方原片軌道紅色是重講、灰色是停頓，綠色表示保留。點區塊後，在「粗剪」試看片段、確認刪除或取消刪除；也能手動加入刪除範圍。原片不會被改寫。
6. 下方字幕軌道顯示**剪輯後時間**，確認剪輯後立即更新。若切入詞語或人工修字範圍，字幕標示黃色，需核對文字／時間，再按「此段已試聽確認」。
7. 「腳本校正」頁顯示原辨識、建議文字、參考腳本與理由，可採用或撤銷。已有手動修字的片段以人工內容優先。
8. 按「儲存編輯」一次保存剪輯、字幕及樣式。輸出時可直接按「儲存並輸出 MP4」或「儲存並下載 SRT」。取消「顯示／輸出字幕」可輸出無字幕粗剪，修字仍保留。

文字、拖曳、樣式、播放與定位都在瀏覽器處理，不會重跑 Python、重新辨識、呼叫 Gemini 或執行 FFmpeg。正式輸出才使用後端既有 FFmpeg 流程。已完成且內容未變更的 MP4 會沿用，按儲存不會使它失效。輸出失敗時已保存的編輯仍在。

瀏覽器利用保留片段清單跳轉，受 seek 精度及解碼延遲影響，**切點預覽不保證逐影格等同成品**。成品仍由 FFmpeg 精準裁切；請試聽最終 MP4。預覽和燒錄使用相同字級、底部百分比、顏色及換行；瀏覽器系統字型與伺服器 Noto 字型的字形、行高可能略有差異。

舊介面仍保留：勾「顯示進階表格與原片試聽」可用既有表格、版本恢復及單張預覽。不要同時在兩套介面保留不同的未儲存修改；版本衝突時新版編輯器會阻止覆寫。

## 腳本輔助校正

`core/subtitles/correction.py` 在本機將辨識短句與最接近的腳本句／視窗對齊，最多提出少量字元替換，保留原標點及可用的聲學詞語時間。原稿只是參考，沒有說出的句子不會補進字幕。

- **自動校正**：限定經測試的同音字集合、高文字重合度、足夠上下文及室內設計詞語證據，例如「三成收納」→「三層收納」。可撤銷。
- **建議確認**：近音、局部專有詞差異或數字／單位差異；預設保留辨識，必須使用者採用或手動修正。數字、價格、尺寸、日期指紋不同時絕不自動替換。
- **保留原文**：明顯改講、缺句、對齊不足或不屬於可解釋的局部替換。

這是保守的字詞規則與文字對齊，沒有通用聲韻理解，也不把內部分級宣稱為校準機率。字典外或音似但不同字數的專有名詞仍需人工核對。沒有新增 AI 請求或辨識套件。

資料分開保存：`transcript` 為聲學辨識；`original_cues` 為校正前字幕；`corrections` 為建議、理由及決策；`cues` 為目前可交付版本。人工字幕有 `manual` 標記，重新產生時保留，重疊的新自動字幕會避開人工時間範圍。人工確認的事實差異也視為人工選擇。編輯不改動語音辨識、停頓或重講依據。

## 時間軸與資料交換

每段字幕保留原片 `spans`，未手改的字幕也保留量測的詞語 `atoms`。已確認刪除範圍合併後，推導保留片段及雙向映射：

```text
輸出時間 = 原片時間 − 此保留片段原片開始 + 此保留片段輸出開始
```

刪除原片 5～10 秒，原片 10～15 秒的字幕會移到輸出 5～10 秒。修改輸出時間時逆映射回原片座標；取消刪除可按原片資料恢復。涉及被切到的字詞／人工修字時要求再次確認，不猜測要保留哪些文字。

Python 的 `core/subtitles/mapping.py` 是正式映射與輸出驗證依據；`editor_model.mjs` 在瀏覽器鏡射相同規則供即時互動。已保存字幕的換行使用 Python 詞界結果；尚未保存的剪輯預覽先用瀏覽器 `Intl.Segmenter` 詞界，保存後以 Python 結果為準。

Python 傳送專案識別碼、來源雜湊、revision、影片尺寸／長度／媒體參照、字幕來源、原始辨識參考、校正選項、剪輯決策及樣式。只有保存／輸出按鈕觸發元件的 `commit` 訊號，傳回：

```text
protocol, operation_id, base_revision, source_sha256,
captions[id, spans, text, highlights, confirmed],
cuts[id, start, end, selected, confirmed],
corrections[id, decision], style, enabled
```

請求不含影片 bytes、API 金鑰、FFmpeg 指令、任意路徑或客戶端聲稱的詞語對齊。`core/editor/service.py` 限制大小、欄位、時間範圍、重疊、識別碼、確認狀態及樣式；只信任伺服器已有的詞語／校正選項。新增文字一律視為人工修改。SQLite 樂觀鎖一次交易保存剪輯及字幕；相同操作識別碼重送不重寫，相同識別碼卻不同內容會拒絕。

## 草稿與衝突

輸入停止約800毫秒後，未保存資料寫入**目前瀏覽器 localStorage**；僅明確儲存／輸出時同步 SQLite。保留最近10筆可恢復撤銷紀錄，編輯期間最多50筆；草稿過大時省略撤銷歷史，避免佔用過多空間。草稿有效期7天，共用電腦請保管好資料。關閉瀏覽器前會嘗試寫入草稿並要求瀏覽器提示；無痕模式、封鎖儲存或瀏覽器未觸發離開事件時不保證可恢復。

重新開啟同一專案，可恢復同來源、同版本草稿。另一視窗已保存時會阻止舊版本覆蓋，可先下載草稿，再重新載入專案版本。下載的瀏覽器草稿是衝突救援紀錄，目前沒有自動合併／直接匯入功能；正式可恢復備份仍使用既有剪輯專案 JSON 及原片。

保存期間仍可繼續修字：收到確認後只清除已送出的快照，後續修改維持未保存，不被伺服器回應蓋掉。

## 效能觀察

舊字幕表格本來就在 Streamlit form 中，打字本身也不會逐字重跑；原先不足是看不到即時影片字幕，必須保存後另按 FFmpeg 單張預覽。這次改善的是即時回饋及分散的操作流程。

實測 Windows、192×320、8秒合成片、2段字幕：一次文字修改約9.30ms，拖曳後兩次修改平均5.60ms，單次樣式修改約0.70ms，均為瀏覽器事件處理時間，**不是畫面繪製延遲或大型專案基準**。可展開「儲存與操作狀態」查看目前工作階段自己的計數及最近120次平均耗時。沒有宣稱固定提升百分比。

上述修字、樣式、定位、拖曳及粗剪操作期間，編輯器同步次數0，SQLite仍為原revision，沒有輸出檔；按輸出才保存及執行FFmpeg。8秒示範刪0.5秒停頓後，字幕4.10→3.60秒，MP4為7.5秒，音／畫軌長度差約0.067秒，通過既有同步檢查。再按一次輸出，檔名及修改時間維持不變。

另外發現 `st.video(path)` 的媒體登錄會在重跑時重新讀取整部影片並重算媒體指紋（1.65對大檔使用部分雜湊），舊備份下載也會預先讀取內容。新版用 `ui/media_reference.py` 隔離 Streamlit 媒體參照續用，測試20次登錄只讀1次，資源淘汰時才重新讀取；備份與MP4下載改為點擊後才讀取。播放及字幕點選維持同一 `<video>` 資源，不以 base64 重送影片。

## 部署與限制

- 保持 `streamlit==1.65.0`，使用 Custom Components v2。原生JS、ES module及CSS直接放在 `ui/frontend/` 隨Git部署，**不需要 Node/npm、React、前端建置或CDN**。Node只用來執行開發測試。
- 沒有新增 Python 依賴；沿用 `requirements.txt`、`packages.txt` 的 FFmpeg、Noto CJK、fontconfig、OpenCC、jieba及fonttools。Windows字型不可當作Cloud依賴。
- 媒體參照介面封裝少量 Streamlit 私有API；只支援並測試目前固定版本。未來升級Streamlit需重跑該介面、元件註冊及瀏覽器播放測試。瀏覽器URL依當前部署路徑解析，適用Cloud代理路徑。
- 「字幕環境檢查」先跑短小合成燒錄測試；再勾「試用視覺化編輯器（合成示範）」可在獨立SQLite與暫存目錄測試播放、儲存及輸出。合成示範不加入正式專案，暫存生命週期跟隨瀏覽工作階段，不呼叫AI／ASR。
- 仍沿用本機 SQLite／影片磁碟；Cloud休眠、重啟或重新部署可能遺失。瀏覽器草稿不能取代原片及專案JSON備份。這次沒有新增永久雲端儲存。
- 媒體伺服器仍需保留來源／成品bytes，長影片受Cloud記憶體限制；500MB／15分鐘是既有上限，不代表共享主機都能流暢處理。建議短片並在本機處理大檔。沒有把完整影片放進元件資料或每次編輯訊息。
- 使用桌面瀏覽器編輯。手機採上下排列可查看；精細拖曳建議使用滑鼠。瀏覽器字型與成品仍請人工比對，實拍的口音、專有詞及極短切點需要人工驗收。
